# A. 强调色通胀与数据色撞车

## A.1 事实

`theme.ts` 的五个主题里，**四个强调色与四个数据色在默认主题下逐值相同**：

| 令牌 | 默认值 | 数据色 | 同值 |
|---|---|---|---|
| `--accent` | `#ffd47e` | `CLASS_COLORS.goldilocks` | **是** |
| `--accent-2` | `#37e2c8` | `CLASS_COLORS.candidate` | **是** |
| `--accent-3` | `#b389ff` | `EXPLORATION_COLOR`（生成星） | **是** |
| `--accent-4` | `#6ea8fe` | `CLASS_COLORS.lead` | **是** |
| `--danger` | `#ff6b7a` | 无 | 否 |

这不是「金色用得多」，是**装饰色与数据色共用同一组值**。

### 后果一：语义无法区分

同一个 `#ffd47e` 在页面上意味着「品牌」「可点」「重点」「宜居带分子」四种完全不同的东西。

### 后果二：换主题时数据色分裂（已实测）

`.badge--goldilocks { color: var(--accent) }` 跟随主题，而图例圆点用内联的 `CLASS_COLORS` 不跟随：

| | cosmos | abyss |
|---|---|---|
| `.badge--candidate` | `rgb(55,226,200)` | `rgb(63,214,184)` ← 变了 |
| `.legend__dot` | `rgb(55,226,200)` | `rgb(55,226,200)` ← 没变 |

**同一屏、同一类别、两种颜色。** 这直接违反 `HANDOFF §四` 的硬约束「不改 `CLASS_COLORS` 色值——那是数据编码色」。

### 后果三：默认主题下四个强调色被数据色「锁死」

如果按品牌需要调整强调色，默认主题下会连带改动数据色语义。

### 金色用量实测

- 全页金色文字 **23 处**，金色元素 **38 个**
- 9 个章节标题里 **8 个**是同一句式（中性前半句 + 金色后半句）
- `color: var(--accent)` 作纯文字色出现在 **11 个选择器**

## A.2 两个方案

### 方案 A1：只解绑数据色（最小、最安全）

数据色不再走主题变量，强调色保持现状。

```css
/* 徽章改用固定的数据色，与图例圆点同源 */
.badge--goldilocks { color: #ffd47e; border-color: rgb(255 212 126 / .5); }
.badge--candidate  { color: #37e2c8; ... }
.badge--lead       { color: #6ea8fe; ... }
.badge--generated  { color: #b389ff; ... }
```

- **改**：`styles.css` 5 条徽章规则 + `.mol-panel__custom`
- **不改**：`theme.ts` 一行都不动
- **解决**：后果二（主题下颜色分裂）
- **不解决**：后果一（默认主题下仍不可区分）、后果三
- **风险**：极低。徽章在四套非默认主题下会**变色**（从主题色变成固定数据色）——这是修复，但要接受视觉变化
- **代价**：约 20 行 CSS

### 方案 A2：语义分层 + 金色收缩（推荐）

把「装饰」与「数据」拆成两套令牌，并给金色划死职责。

**第一步：`theme.ts` 新增数据色令牌，五套主题都写同一组值**

```ts
const DATA_COLORS = {
  '--data-goldilocks': '#ffd47e',
  '--data-candidate':  '#37e2c8',
  '--data-lead':       '#6ea8fe',
  '--data-far':        '#5a6788',
  '--data-generated':  '#b389ff',
}
```

这样 CSS 里可以写 `var(--data-goldilocks)`，而不是把十六进制撒进样式表。
（`galaxy.ts` 的 `CLASS_COLORS` **不动**——它仍是被 107 条测试保护的数据源；这里是 UI 层的镜像。）

**第二步：强调色与数据色脱钩**

默认主题的 `--accent` 从 `#ffd47e` 调开，让「品牌金」与「宜居带金」不再同值。

推荐 `--accent: #f5c451`（更饱和、偏琥珀，与 `#ffd47e` 相邻但可区分）。
其余三个强调色同步调开一档。

**第三步：金色收缩到三种角色**

| 保留 | 移除 |
|---|---|
| 品牌字标 `.topnav__brand` | `.funnel__value` 漏斗数值 |
| 主 CTA `.btn--primary` | `.timeline__year` 时间轴年份 |
| 章节标题重音 `.accent-text` | `.compare__best` 最优值标记 |
| | `.shortlist--open` 展开态 |
| | `.footer__links a:hover` |
| | `.mol-panel__action--on` 收藏态 |

移除的改用：`--text`（正文白）或 `--accent-2`（青，本就在做「信息/数据」的活）。

**第四步：八个同句式标题拆开**

现状 8/9 同构。改为三种句式交替：

| 章节 | 现标题 | 建议 |
|---|---|---|
| pipeline | 一粒药要经过的**五道关卡** | 保留（这是「流程」句式，最贴切） |
| funnel | 一万个候选，**一个赢家** | 保留（数字对比，有力量） |
| stats | 这片宇宙的**人口普查** | 改为陈述句：**600 颗星，四种成色** |
| compare | 把候选分子**摆在一起看** | 保留（动作句） |
| lab | 换个权重，**整片星系重排** | 保留（因果句，全站最强） |
| timeline | 三十年，**从数得清到算得动** | 保留（对仗） |
| method | 这片宇宙是**怎么算出来的** | 改为陈述句：**每一个数字都可以复核** |
| limits | 这个工具**不能**告诉你什么 | 保留（否定句，收尾有力） |

只改 2 个。**理由是这 2 个目前是「疑问句/指代句」，与其余 6 个的「陈述/动作」不同构，反而更该统一到陈述句。**

> 注意：改标题要动 `i18n.tsx`（中英各一条），且 `accent-text` 的 span 位置要跟着调整。

## A.3 取舍：数据色要不要彻底脱离金色

**这是需要你定的关键取舍。**

「宜居带」是本站的核心隐喻，而金色是它的颜色标识。若把 `--accent` 调开：

- **好处**：品牌金 ≠ 数据金，读者能区分「这是要点的」和「这是数据」
- **代价**：首屏的 `10⁶⁰` 与「一片获批的药」是品牌金，而星系里最亮的星是数据金——两者不再同色，**视觉上少了一层呼应**

我倾向**接受这个代价**：数据色应该在数据里说话，品牌色应该在 CTA 上说话。混在一起才是当前的问题。

但如果你想保留「首屏金色 = 星系金色」这层呼应，那就只能走 A1，并接受默认主题下四色不可区分。

## A.4 验收

- `npx vitest run` 168/168（`urlState.test.ts` 有主题相关断言，注意）
- `npm run build`

- **新增**：确认 `CLASS_COLORS` 一个字节没变（`git diff src/lib/galaxy.ts` 应为空）

# B. 九章节奏：外框统一但内里同质

## B.1 事实

| 章节 | 高度 | 屏 | 内里形态 | 同款矩形数 |
|---|---|---|---|---|
| pipeline | 4798 | **5.33** | 横向舞台 | 5 |
| timeline | 1293 | 1.44 | 单轴 + 卡片 | 5 |
| lab | 1107 | 1.23 | 滑块 + canvas | 0 |
| method | 948 | 1.05 | 编号行 | 0 |
| cosmos | 872 | 0.97 | 3D 星系 | 0 |
| funnel | 682 | 0.76 | 锥形 | 4 |
| limits | 574 | 0.64 | **圆角矩形列表** | 4 |
| stats | 477 | 0.53 | **圆角矩形网格** | 4 |
| compare | 373 | **0.41** | 芯片 + 表格 | 0 |

**外框完全统一**：96px 上边距 / eyebrow 12.5px 青 / 标题 36.8px 800 / lead 16px / 44px 间距，九章一律。

**内里**：5 章是「N 个同款圆角矩形」，其中 **stats 与 limits 的卡片几何完全一致**（`border-radius` 不同：`--radius` vs `--radius-sm`），只有边框色不同（`--line` vs 红 0.28）。

后果：滚过去每章开头都一样，没有起伏；compare 只有 373px，夹在 477 与 1107 之间像呼吸中断。

## B.2 改法（三件事）

### B2-1：limits 去掉卡片外壳（改动最小，收益最大）

「边界声明」是四条**否定句**。用卡片装否定句，语义是反的——卡片意味着「这是一个可点/可比较的单元」。

改为**无边框列表 + 红色左竖线**：

```css
.limits-list { gap: 0; }
.limits-list li {
  border: 0;
  border-left: 2px solid rgb(255 107 122 / 0.5);
  border-radius: 0;
  background: none;
  padding: 16px 0 16px 18px;
}
```

- 九章里的「同款矩形」从 5 章降到 4 章
- 与 `method` 的编号行形成同类（都是「无壳的行」），但一个用数字列、一个用色条，不撞
- 改动：`styles.css` 1 条规则

### B2-2：stats 与 compare 合并

`compare` 只有 373px，且**它的空态是一个死路**（章节内可操作元素 = 0，而星系在上方 6828px）。

合并方案：把 compare 降级为 stats 的第二个子块——「普查」讲「这 600 颗星是什么成色」，紧接着讲「把它们摆在一起看」是自然的。两者都在讲「分类与比较」。

- 九章变八章，导航 9 项变 8 项
- compare 不再独立成章，373px 的「呼吸中断」消失
- 改动：`Sections.tsx` 组合 + `Sections2.tsx` 的 `NAV_SECTIONS` + `i18n.tsx` 的 `nav.compare`
- **风险**：动了导航结构，`verify-stage.mjs` 的 T6/T7 与 `verify.mjs` 的几何断言要复核

> **这一条我建议单独一轮做**，因为它动导航和章节顺序，混在 B 里会说不清回归来源。

### B2-3：行宽统一到参数

现状：时间轴 55 字/行、方法 50 字/行、普查 17 字/行。

引入一个 `--measure` 令牌，统一到 **34 字左右**（CJK）：

```css
:root { --measure: 34em; }  /* ≈ 34 个全角字 */
.timeline__body, .method-row__body { max-width: var(--measure); }
```

普查卡片 17 字是**布局决定的**（4 列 × 233px），要改就得从 4 列改 2 列 —— 那会拉长章节。**建议普查不动**，只在时间轴/方法上收紧。

## B.3 验收

- 三套 verify 全过（B2-1、B2-3 不涉及几何断言）
- 九章逐章截图，确认「同款矩形」从 5 章降到 4 章

# C. 长舞台：80% 留白 + 全程无标题

## C.1 事实

```
.stage-pin      836px   (calc(100vh - 64px))
卡片            227px   (距 pin 顶 273px)
上方空白        337px
下方空白        336px
                 673 / 836 = 80%
```

3640px 的行程里，章节标题一直在视口外：

| 位置 | `.section__head` top |
|---|---|
| pin 起点 | **−206px** |
| pin 中段 | −2026px |
| pin 末端 | −3846px |

横向暗示只有三样：第 3 卡被右缘切、`01 / 05` 计数器（12.5px / 3.89:1）、2px 进度条。

## C.2 改法（两件事，都不动 `useStageTravel`）

### C2-1：把标题固定进 pin 区

不是把 `.section__head` 搬进来（那会动 DOM 结构与 `Sections.tsx`），而是**在 `.stage-pin` 里加一个精简标题**：

```jsx
// StationStage.tsx 内新增
<div className="stage-caption">
  <span className="stage-caption__eyebrow mono">{t('pipeline.eyebrow')}</span>
  <h3 className="stage-caption__title">{t('pipeline.title.short')}</h3>
</div>
```

配合 `justify-content: center` 改成 `flex-start` + `padding-top`，让标题、卡片、计数器成为一个垂直组。

- 新增 1 条 i18n key（短标题，中英各一）
- 改动：`StationStage.tsx` + `styles.css`
- **不动** `useStageTravel.ts`，不改变 travel/span 的算法

### C2-2：留白从 80% 收到 ~45%

当前 `.stage-pin` 是 `height: calc(100vh - 64px)` + `justify-content: center`，卡片只占 227px。

改法：让 pin 高度跟着内容走，而不是撑满视口：

```css
.stage-pin {
  height: auto;            /* 不再撑满视口 */
  min-height: calc(100vh - 64px);
  padding: 96px 0 64px;    /* 上：让出标题；下：给计数器 */
  justify-content: flex-start;
}
```

效果：卡片上方是标题，下方是计数器与进度条，三者成组居中。**留白从 673px 降到约 200px（标题 + 间距 + 计数器）。**

- 风险：`ScrollTrigger` 的 `end` 用 `stageSpan()` 计算，与 pin 元素高度无关（用的是 `+=span`），所以**不影响 pin 的行程**
- **但 `start: 'top 64px'` 依赖元素顶部位置** —— pin 变高会改变 start 的文档位置，需要复核 `verify-stage.mjs` 的 T2

### C2-3：计数器加强

`12.5px / #5f6c92 / 3.89:1` → `14px / var(--text-dim) / 8.44:1`，进度条 `2px → 3px`。

## C.3 验收

- `verify-stage.mjs` T1/T2/T6/T8 全部重跑（T2 测「轨道是否横移」，pin 高度变了要确认行程仍正确）
- 1440 / 768 / 390 三档
- reduced-motion 下确认堆叠仍正常（上一批刚修的，别回归）

# 三、总体取舍与建议顺序

| 顺序 | 内容 | 改动面 | 风险 | 观感变化 |
|---|---|---|---|---|
| **1** | **A1 或 A2** | `styles.css`（+ `theme.ts`） | 低 | **大** |
| 2 | B2-1 + B2-3 | `styles.css` | 低 | 中 |
| 3 | C2-1 + C2-2 + C2-3 | `StationStage.tsx` + CSS | 中 | 大 |
| 4 | B2-2（合并章节） | 三文件 + 导航 | **高** | 中 |

**理由**：A 是纯色彩令牌与规则，改动集中、回归可预测、观感立刻不同；C 要动组件与 pin 几何，需要重跑验收基线；B2-2 动导航与章节顺序，风险最高，建议最后单独做。
